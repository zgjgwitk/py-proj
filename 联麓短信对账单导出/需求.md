# 联麓短信对账单导出

## 提炼后的目标
把原 PRD 里的“运营后台导出联麓短信对账单”压缩成一个本地 Python 脚本：

1. 直接请求 ES `_search` 接口。
2. 只查联麓短信数据：`smsChan = 40`。
3. 不传 `month`，直接查询索引内的全部数据。
4. 生成一个 Excel 文件。

不再实现这些内容：

1. 不接 OPC 页面。
2. 不做超级管理员权限校验。
3. 不查品牌配置、账号配置、短信账号配置。
4. 不生成复杂的跨系统 DTO。

## 输入参数

脚本最少需要以下参数：

1. `es_url`：ES 地址，示例 `http://127.0.0.1:9200`
2. `index`：索引名，示例 `esmsgsms2605`

可选参数：

1. `headers`：自定义请求头，适配网关/鉴权
2. `brand_ids`：只导出指定品牌
3. `sms_chan`：默认 `40`

## 使用的 ES 字段

当前按已有资料只依赖这些字段：

1. `brandId`
2. `ezrAcc`
3. `serviceType`
4. `reqTime`
5. `reqTimeDay`
6. `chargeNum`
7. `resStatus`
8. `smsChan`

说明：

1. 这版脚本不依赖 `brandName`、`smsAccount` 等业务配置字段。
2. 如果 `ezrAcc` 为空，按“默认账号”展示。

## 统计口径

### 汇总 sheet
按 `brandId + ezrAcc + serviceType` 聚合，输出：

1. 品牌编号
2. EZR账号
3. 产品类型
4. 开始时间：当前聚合 bucket 内最早 `reqTime`
5. 结束时间：当前聚合 bucket 内最晚 `reqTime`
6. 提交量：ES 文档条数
7. 总计费量：`sum(chargeNum)`
8. 成功计费量：`resStatus = 3`
9. 失败计费量：`resStatus in [2,4,5]`
10. 未知计费量：`resStatus = 1`

### 明细 sheet
按 `brandId + ezrAcc` 分 sheet，sheet 内按 `reqTimeDay + serviceType` 聚合，输出：

1. 发送日期
2. 产品类型
3. 提交量
4. 总计费量
5. 成功计费量
6. 失败计费量
7. 未知计费量

## Excel 结构

1. 第一个 sheet 固定为 `各品牌汇总`
2. 后续每个 sheet 为一个 `brandId_ezrAcc`
3. sheet 名超出 31 个字符时自动截断并去重

## ES 查询方式

脚本使用两段聚合 DSL：

1. 汇总查询：`brandId + ezrAcc + serviceType`
2. 明细查询：`brandId + ezrAcc + reqTimeDay + serviceType`

都使用 `composite aggregation` 分页拉全量 bucket，避免一次性 terms 聚合过大。

## 运行方式

示例：

```bash
python export_ll_statement.py --config config.example.json
```

或者直接传参：

```bash
python export_ll_statement.py ^
  --es-url http://127.0.0.1:9200 ^
  --index esmsgsms2606 ^
  --output 联麓对账单_esmsgsms2606.xlsx
```

## 与原方案的主要差异

1. 原方案按“品牌配置 + 账号配置”组织范围，这里改成直接以 ES 明细里实际存在的数据为准。
2. 原方案有 `BrandName`、`SmsAccount`、权限校验，这里全部去掉。
3. 原方案强调跨系统接口，这里只保留一个本地脚本。
4. 原方案有“提交成功量”等复杂口径，这里收敛为 ES 可直接稳定算出的指标。
